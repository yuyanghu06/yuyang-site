# City tile outputs

This directory contains the immutable full CityGML building tiles and metadata, plus a separately derived compact Manhattan overview. There are no direct subfolders. All coordinates retain the Washington Square origin.

Regenerate full tiles with the city-tile script; do not edit individual GLBs manually. That script preserves this guide while clearing stale outputs and automatically regenerates the overview and compact details after its final manifest/runtime writes. Tile and overview URL versions must follow their respective content metadata for immutable-cache correctness.

## Direct metadata and overview files

- `manifest.json` lists every full-detail tile, its center and the source version. It remains the neighborhood loading contract.
- `runtime.json` preserves full building footprints and landmark surface details for offline generators. The browser uses the compact details file instead.
- `details.json` contains only `{ "details": ... }`, exactly matching `runtime.json` landmark details (66,195 bytes).
- `overview.glb` contains one noninteractive Manhattan overview: all original wall/roof triangles from the 405 eager-coverage tiles in two batches, plus the existing 70 park grass rings in a third batch. All eight tile-omitted landmarks are restored inside those building batches: six exact runtime base buildings plus the exactly fitted Bobst/arch source models. The seventh runtime detail record already exists in the tiles and is not duplicated. It is 4,919,020 bytes, 66.29% below the original 14,591,908-byte building download. Decoded buffer-view capacities fall from 43,231,722 to 23,308,716 bytes (46.08%); these figures exclude roads and whole-app memory. Building grounds, normal buffers and procedural close-view trim/windows are omitted. Exact source tile RGB bytes and wall/roof triangle topology remain; curated runtime/model colors round to 8-bit RGB. Building positions have a checked bake-plus-quantization error below 7 cm. Park positions stay Float32 at the exact existing 0.74-meter elevation.
- `overview-manifest.json` records content hashes, source tile/park/model provenance, all nine curated coverage records, exact model-fit matrices, eager-coverage selection, positional/color-error measurements, geometry/download/memory counts and runtime material requirements. Apply the existing `NotEqualStencilFunc`/reference 1 road mask to `overview-park-grass` after decoding; glTF cannot store that Three.js stencil state.
- `info.md` is this authoritative folder guide.

Run `node scripts/map-data/build-manhattan-overview.mjs` after changing the full city tiles, fitted Bobst/arch models, park rings or generated ambient context rings. The command writes only the three derived overview/detail files, performs no downloads, and verifies decoded geometry, retained wall/roof triangle counts, bounds and palette. Full tiles and `runtime.json` stay unchanged. Overview objects have no interactive landmark metadata; neighborhood views use their original full assets.
