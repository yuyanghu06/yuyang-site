# Manhattan loading

This directory owns prepared Manhattan overview and exact neighborhood layers. There are no direct subfolders.

- `info.md` is this folder guide.
- `manhattan-loader.ts` exposes idempotent `ensureOverview` and `ensureNeighborhood` promises, readiness/visibility controls, cancellation and disposal. Constructing the controller starts no requests. First New York intent reads the revalidated overview manifest, loads its content-hashed overview GLB and exact stencil-first roads, and prepares shared park scenery before the cloud reveal. The overview contains noninteractive city buildings and exact minimal park grass; the runtime restores the grass stencil state after decode. The browser never fetches the large `runtime.json`.

The first overview preparation lazily imports the existing ambient layout and park/plaza/garden factories and reads the small Washington Square and Union Square park datasets (29,874 and 56,497 bytes). One shared scenery group retains all 624 authored park trees (88 Washington, 80 Union/Gramercy and 456 context), 919 path segments, 19 mapped crosswalks, the initialized Washington fountain, Gould Plaza's five trees and nine seats, and the Courant garden's seven trees. The existing factories preserve positions, colors and geometry. This group stays visible in Manhattan, Washington and Union without duplicate neighborhood geometry; its fountain animates in all three views. Existing overview/detail grass remains separate and is not duplicated in the shared group.

Washington/Union navigation reuses the loaded park data/factories, reads compact content-hashed `details.json`, and prepares unchanged merged landmarks and population. Exact CityGML tiles are limited to the destination's 900-meter neighborhood and decoded four at a time. Geometry remains off-scene until every required tile/model succeeds. No tile arrival springs remain to stream beneath a reveal; the previous visible layer remains intact during preparation. Returning to Manhattan hides exact layers and restores the compact overview. Prepared exact tiles and both neighborhood readiness sets cache for revisits.

Requests deduplicate while pending, retry after failure, and reject superseded navigation. Partial landmark registration rolls back for a clean retry. Overview preparation observes all building, road and park siblings before either atomically mounting them or releasing every successful sibling. Partial park construction releases already-attached geometry and instance buffers; failed data requests retry. Failed or late overview/road/tile/custom decodes, unmounted shared scenery and prepared detail are disposed, including after teardown; mounted layers belong to the runtime's shared scene traversal. Source groups used to bake selectable landmarks release their original geometry/material/instance buffers. Population updates only in visible neighborhood views.
